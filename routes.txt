## One design suggestion

Since **Admin and HR are the only people who can create accounts**, I would **remove the `POST /api/auth/register` endpoint entirely**. Your authentication module only needs:

* `POST /api/auth/login`
* `POST /api/auth/refresh-token`
* `POST /api/auth/logout`
* `GET /api/auth/me`

Account creation belongs in the `User`/`Employee` modules, protected by role-based authorization. This reflects how most enterprise HRMS applications are designed.

## One important recommendation

Since **HR creates employees**, I would **not** expose a separate `POST /api/users` endpoint for creating employee accounts.

Instead:

* `POST /api/users` → Create **Admin**, **HR**, or **Manager** accounts.
* `POST /api/employees` → Create an **Employee**, and inside that controller:

  1. Create the `User` record (role = `"employee"`).
  2. Generate the `employeeId`.
  3. Create the `Employee` record.

This keeps the API aligned with the business process: HR thinks "I'm adding an employee," not "I'm creating a user and then an employee." It also avoids orphaned `User` records with no corresponding employee profile.
